# The Westlakers

## Branching Strategy
Given the size of the team and scope of the project, a flexibile, frequently changing trunk-based strategy will be the approach taken for the development of the project.
Each member will use an individual, ideally short-lived branch that is as up to date as possible to the main branch to contribute to any features/fixes.
The naming convention for each branch will be in the format of feature/action. For example: feature/login, feature/auth. For any fixes or improvements, the form feature/action/fix|improvement will be utilize. For example: feature/login/auth_fix, feature/ui/re=format.
